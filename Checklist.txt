Duck compiler checklist
Language design: README.md | Bootstrap implementation: Compiler

Concurrency and locking
[x] Schedule independent work for parallel execution.
   Proposal: Start with calls whose effects are known. Lower independent calls to worker tasks, join at the first dependent use or scope exit, and compare output against sequential execution with one and several workers.
[] Track resource reads and writes across calls and wait for conflicting earlier work.
   Proposal: Add read/write summaries to function signatures. Propagate effects through recursive call groups, map parameters back to caller resources, and treat unknown native effects as a synchronization barrier.
[] Implement ordered ${ ... } blocks that lock resources used by the block and its callees.
   Proposal: Parse an ordered-block statement. Acquire its transitive resource set in stable identity order and reuse locks held by an enclosing block. For effects that cannot be resolved before entry, begin with a shared scheduler-wide exclusion mechanism.

Ownership and null safety
[] Support owning container fields and reject moves that would create an ownership cycle.
   Proposal: Represent an owning field separately from a raw C-layout pointer. Check the proposed parent's ancestor chain before committing a move so a rejected cycle leaves the original owner intact.
[] Track aliases stored in fields, collection entries, and captured lambdas so they expire when the owner releases the resource.
   Proposal: Promote an escaping local alias to the existing heap control block. Generate retain/release operations when aggregate slots are copied, overwritten, or destroyed. Test that an expired collection entry stays present and compares equal to null.
[] Defer destruction until active uses of a resource finish.
   Proposal: Extend heap control blocks with an active-use count. Atomically close the object to new uses on destruction, then let the last active user trigger cleanup exactly once.
[] Support pointer conditions such as if p and protect the checked use.
   Proposal: In condition analysis, recognize a checked pointer and bind the successful branch to its evaluated reference. For tracked objects, pin that object through the guarded use and release it on every branch exit.
[] Support guarded call chains such as ?o.ex.Foo().
   Proposal: Parse a leading guard on a call chain. Evaluate each receiver once, skip the remainder on the first invalid link, and retain each live receiver through the call. Test that skipped arguments have no side effects.
[] Support factories that return ownership on one path and a tracked alias on another.
   Proposal: Infer the possible return roles across all branches and carry the actual role with the returned handle. Promote escaping aliases before local cleanup so an alias to a local owner arrives expired while one to a surviving owner remains usable.
[] Resolve how ordinary inference (cake : MakeCake(...)) should receive a returned owner, then align the compiler and README example.
   Proposal: Proposed rule for review: a fresh inferred local consumes an owning result and preserves a borrowed result as an alias. Specify how explicit :: handles a borrowed result before enabling mixed factories; cover both return paths in the factory tutorial.

Containers and namespaces
[x] Parse + and - member access modifiers and enforce protected access.
   Proposal: Store visibility on each member declaration. Use lexer locations to enforce adjacency of the prefix and member declaration, then check the declaring and accessing container during lookup, including inherited protected access.
[x] Support static data fields.
   Proposal: Collect static fields as qualified symbols and emit storage once in the defining module. Route qualified reads and writes to that storage and specify initialization order before allowing initializers that read other static fields.
[x] Support field initializers and managed string/name fields.
   Proposal: Keep initializer expressions on field declarations and type-check them against the field type. Static fields already accept constant initializers; extend them to managed types and, once an order is specified, to initializers that read other static fields. Generate initialization, copy, assignment, and cleanup for managed records using the text runtime; keep their managed layout out of raw native struct bindings.
[x] Allow non-constant field and static initializers.
   Proposal: Specify static initialization order (declaration order within a module, imported modules first) and run it from a per-module initializer before Main. Evaluate non-constant instance defaults in a generated per-container construction routine shared by default construction and partial initializers. Then lift the restrictions on reading other statics, big defaults other than zero, and container-typed initializers, and decide whether managed containers may live on the heap.
[x] Allow a container to chain static and instance blocks.
   Proposal: Parse a named container followed by a sequence of adjacent bodies, tagging each body as static or instance. Preserve the existing adjacency rule and resolve member calls using the receiver kind.
[x] Merge instance container extensions across declarations and files.
   Proposal: Collect fragments by qualified container name before validating layouts. Merge in declared input order, diagnose conflicting members and parent lists at their source locations, and give importing modules the same final field layout.
[x] Support nested instance types and their qualified names.
   Proposal: During name collection, maintain a stack of enclosing containers and register qualified type names. Resolve type paths in declarations, casts, and construction using the same lookup order.
[x] Support namespace imports with using.
   Proposal: Record using directives in their lexical scope. Expand an unqualified name against visible imports during resolution and report both candidates when imports make a reference ambiguous.

Construction and object model
[x] Support custom constructors and destructors.
   Proposal: Register constructor overloads and one destructor per container. Resolve construction by argument types and invoke the destructor from lexical or heap cleanup exactly once for each fully constructed object. Heap drops already run a generated per-container cleanup for string, name, and big fields; run the user destructor from that same hook, before the generated release.
[x] Support partial and composite constructors and reject use before initialization is complete.
   Proposal: Track completed constructor parts in definite-initialization analysis. Compose parent and child parts in a declared order, merge completion facts at branches, and diagnose a method call if any required part may still be missing.
[x] Allow an existing object to be reinitialized by calling its constructor again.
   Proposal: Resolve a call on an existing mutable object as reinitialization. Define cleanup of its previous field values and preserve receiver identity so aliases still refer to the same object after construction completes.
[x] Implement inheritance, multiple parents, and left-to-right parent priority.
   Proposal: Store ordered parent lists, reject inheritance cycles, and compute each base's field layout and offset. Search inherited members left to right and retain the declaring parent for explicitly qualified access. Extend Analyzer::requireAccess so a derived container can use its parents' protected members.
[x] Implement method overrides, virtual dispatch, and base member calls.
   Proposal: Identify overridden signatures after the inheritance graph is complete. Emit dispatch slots for overrides and adjust the receiver to the declaring base; lower base calls directly so they bypass the overriding method. Replace the redeclared-member rejection in resolveInheritance with signature matching.
[x] Allow a derived container to satisfy an interface-style parameter.
   Proposal: Use the declared parent relationship to check interface arguments. Pass a reference to the compatible base view and dispatch to the concrete implementation so a call through the parameter preserves overrides.
[x] Implement getter and setter blocks.
   Proposal: Parse getter and setter bodies as named accessors. Resolve property reads to a getter and assignments to a setter with a typed value parameter; evaluate the receiver once for compound assignment.

Collections
[x] Implement fixed-size and dynamic arrays.
   Proposal: Represent a fixed array with an element type and compile-time extent. Give dynamic arrays data, length, and capacity fields, and generate element-aware moves and cleanup when storage grows or leaves scope.
[x] Implement queues, stacks, and keyed pair collections.
   Proposal: Use a ring buffer for queues, end insertion/removal for stacks, and keyed storage with insertion order for pairs. Preserve the documented first-out, last-out, and last-added-key behavior in runtime tests.
[x] Support collection literals and collection type inference.
   Proposal: Let the expected type disambiguate record, sequence, and pair literals. Without an expected type, infer compatible element or key/value types and diagnose empty or heterogeneous literals whose type cannot be determined.
[x] Support indexed reads and writes, IsValid checks, and guarded indexing.
   Proposal: Add an indexed expression that can denote writable storage. Evaluate the collection and index once and reuse the bounds result for guards and IsValid. Specify the result type of an invalid guarded scalar read before allowing it in value expressions.
[x] Implement collection length, insertion, removal, clearing, and result-producing mutations.
   Proposal: Resolve each mutation by collection kind and apply element cleanup on replacement or removal. First settle whether (s += x) returns the inserted index or the new count, then test empty collections and the first insertion.
[x] Support multidimensional arrays and negative-index dimensions.
   Proposal: Store each fixed dimension's extent and check it before computing a flattened offset. Use nested dynamic storage for variable dimensions and sparse signed-coordinate storage for grids spanning int.Min to int.Max.
[] Support collection size hints such as [*] and [50*].
   Proposal: Record the size annotation as an estimate on the array type or declaration. Feed it to the scheduling cost model; a [50*] array must still grow beyond 50 elements without changing program behavior.

Loops and ranges
[x] Support forward and reverse collection iteration.
   Proposal: Lower iteration to an indexed loop or a collection-specific cursor. Define mutation rules per collection and test reverse removal of the current element so its neighbor is neither skipped nor visited twice.
[x] Support inclusive ascending and descending ranges in loops and expressions.
   Proposal: Add a range expression with two integral endpoints evaluated once. In loops, choose the step from their order and stop after emitting the endpoint, before an increment could overflow. Materialize an array when a sequence value is required.
[x] Support loop chaining with | and the documented ordering of outer and inner bodies.
   Proposal: Parse each chained clause with its optional body and lower it to nested loops. Place each outer body before or after its inner loop according to the pipe position and verify the execution order with a trace.
[x] Support do blocks without a trailing while.
   Proposal: Allow a missing while clause after a do body and lower that form to an unconditional back edge. Reuse loop-exit analysis so break establishes the facts available after the loop and continue starts the next iteration.

Types, enums, and constants
[x] Implement char, date, time, and datetime.
   Proposal: Specify whether char represents a Unicode scalar or a code unit, plus date/time ranges, precision, and timezone semantics. Add distinct types with validated constructors and test supplementary characters, leap days, and invalid values.
[x] Implement the custom byte-width integer families iN and uN.
   Proposal: Parse N as a byte count, validate the documented range, and lower integer arithmetic to LLVM integers of 8*N bits. Extend literal bounds, shifts, casts, and printing beyond host integer widths.
[x] Implement big, ubig, tiny, and utiny.
   Proposal: Choose an arbitrary-precision integer representation for big/ubig and a decimal implementation supporting the promised precision for tiny/utiny. Specify rounding and unsigned subtraction behavior before adding literal parsing and runtime arithmetic.
[x] Implement extensible #@ enums with integer, float, and string values.
   Proposal: Collect enum fragments before assigning implicit values. Store each member's name and underlying value so printing a member preserves its name while arithmetic or concatenation can use its value.
[x] Expose built-in type limits such as int.Max.
   Proposal: Recognize qualified numeric type members during expression analysis. Derive Min and Max from the compiler's width and signedness information and emit typed constants, including for non-host widths.
[x] Reconcile the README's uninitialized #int age example with the compiler's initializer requirement.
   Proposal: Proposed resolution: keep the existing initialized-constant rule and change the README example to #int age = 18. Keep a rejection test for a missing initializer and one for reassignment.

Reflection, duck typing, and lambdas
[] Expose type and member metadata, including names, attributes, and GetTags().
   Proposal: Emit a descriptor per container containing its qualified name, members, signatures, and typed attributes. Resolve GetName and GetTags through those descriptors and preserve the declaring parent on inherited members.
[] Implement runtime duck calls (..), method-existence checks, and optional duck calls.
   Proposal: Parse dynamic dispatch separately from ordinary dot calls. Look up the member on the runtime type, validate its signature, and distinguish presence checks, guarded misses, and required calls that fail when absent.
[] Implement func values, indirect Duck calls, and @ lambda expressions.
   Proposal: Represent a Duck callable with a checked signature, function entry point, and optional environment pointer. Lower each lambda body as a generated function and type-check indirect calls against its signature.
[] Capture outer bindings in lambdas.
   Proposal: Compute each lambda's free variables and place captures in its environment. For escaping lambdas, promote referenced local storage as needed and retain tracked aliases without making them owners. Test invocation after the original scope exits.

Entry points and scripts
[x] Accept Main(string [] args) and pass program arguments to it.
   Proposal: Once arrays are available, accept the documented second entry signature and build a Duck string array in the native entry wrapper. Specify whether it includes the executable name and use a Unicode-capable argument source on Windows.
[x] Support executable file-scope statements invoked through Exec("file.dk").
   Proposal: Collect executable file-scope statements into a hidden function per source file. Propose a table of project source paths for Exec dispatch; specify path resolution and missing-file behavior before supporting computed paths.

Compile-time execution and macros
[] Evaluate explicit #Call(...) expressions at compile time.
   Proposal: Evaluate the typed function body and constant arguments in a bounded interpreter that shares Duck's numeric and trap rules. Define allowed effects and report failures at the marked call before substituting the result.
[] Expand typed macro functions at their call sites.
   Proposal: Capture macro bodies as syntax fragments, bind typed arguments once, then expand and validate in the caller's grammar context. Define name hygiene and expansion limits and report both definition and call locations on failure.
[] Implement #define, #if, and #else.
   Proposal: Process balanced conditional blocks before declaration collection so inactive branches publish no names. Keep define values in a separate environment visible to #if and specify whether that environment is file- or module-scoped.
[] Support the Switch/case syntax used in the macro example.
   Proposal: Introduce switch and case nodes, evaluate the selector once, and type-check labels in its context. Specify fallthrough and break targets and test a case produced by macro expansion.

Language tests, markup, and lifecycle
[] Discover and run T blocks as Duck tests and provide T assertions.
   Proposal: Recognize T blocks attached to containers and collect test functions in a test build. Generate a runner with stable test names and implement assertions that report the test and source location on failure.
[] Use Duck test results and timings when evaluating scheduling optimizations.
   Proposal: Run the same tests with sequential and candidate schedules, discard candidates that fail, and compare repeated timing samples on the same inputs. Keep dependency analysis authoritative because passing tests cannot establish race freedom.
[] Parse this { ... } markup, construct element trees, and support element and markup values.
   Proposal: Enter markup parsing only inside a markup context. Resolve tags to container types, type-check attribute expressions against members, and lower each component tree to explicit construction and attachment operations.
[] Support component lookup, child enumeration, and markup returned by functions.
   Proposal: Keep children in declaration order with a per-type lookup index. Diagnose ambiguous singular access, support indexed duplicates, and define how a returned markup tree transfers its children to the receiving tree.
[] Implement named arena lifetimes with [@Play], @start, @end, and if @Play.
   Proposal: Assign each named scope a runtime descriptor containing its arena and active generation. Start initializes its marked variables, end runs cleanup and invalidates that generation, and the active query reads the descriptor. Specify repeated starts and cross-thread use.
[] Implement loop-scoped lifetimes and cleanup on break, explicit end, and program exit.
   Proposal: Lower an annotated loop with scope entry per iteration and cleanup on each outgoing edge. Propagate an explicit end from callees to the loop boundary, avoid double cleanup on break, and close remaining program scopes at shutdown.
